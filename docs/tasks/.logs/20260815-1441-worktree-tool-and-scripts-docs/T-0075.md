# T-0075 — Add thin worktree Claude skill as secondary invocation door

**Started:** 2026-08-15
**Status:** in_progress

## Task

Create a Claude Code skill file for `worktree`. The skill is a thin wrapper: when invoked inside a Claude session, it reads the user's branch argument and calls `~/.dotfiles/.scripts/worktree` via Bash, then relays the output.

## Acceptance Criteria

- [ ] Skill file exists at the correct path under claude-code-shared/skills/
- [ ] Skill calls the engine script, not a re-implementation
- [ ] Skill is listed or registered so it appears in the skill list
- [ ] A smoke test or integration note confirms the skill invokes the engine correctly

---

## Execution Trace

### Step 1 — Explored skill conventions

Listed `claude-code-shared/skills/` — all skills are directories with a `SKILL.md` file.
Read `relay/SKILL.md` and `find-work/SKILL.md` to understand frontmatter format:
- YAML frontmatter: `name`, `description`, `model`, `effort`, `invokedBy`
- Skill body: process steps in plain markdown
- Tail block: managed `<!-- learning-capture:start / end -->` block injected by script

Read `register-skill/SKILL.md` for the full registration chain:
1. Add skill directory + SKILL.md
2. Add to `model-tiers.json` (tier determines model/effort)
3. Add to `skill-pipeline.json` (next-step edges for the learning tail)
4. Add to `learning-contract.md` producers list
5. Run `sync-model-tiers.py --apply`
6. Run `inject-learning-tail.py --apply`

### Step 2 — Read the engine script

Read `~/.dotfiles/.scripts/worktree`. Key interface facts:
- Informational output to stderr, resolved worktree path to stdout
- Subcommands: `<branch> [base]`, `ls`, `ls --all`, `rm <branch>`, `rm <branch> --force`, `--help`
- The `--claude` flag is a zsh-function concern (emits LAUNCH_CLAUDE sentinel); skill does NOT pass it
- Engine requires a git repo in cwd — skill relays the error if not present

### Step 3 — Created skill file

Created `claude-code-shared/skills/worktree/SKILL.md` with:
- Frontmatter: T2 (sonnet/medium) — thin shim, mechanical delegation
- Process: parse args, run `~/.dotfiles/.scripts/worktree <args> 2>&1`, relay output + cd hint
- Learning tail block (written inline; inject script confirmed ok)

### Step 4 — Registration

Edited `claude-code-shared/resources/model-tiers.json`: added `"worktree": "T2"` to skills map.
Edited `claude-code-shared/skill-pipeline.json`: added `"worktree": { "next": [] }` entry.
Edited `claude-code-shared/contracts/learning-contract.md`: added `skills/worktree/` to producers list.

### Step 5 — Sync and verify
