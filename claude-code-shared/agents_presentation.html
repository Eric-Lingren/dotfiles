What the research says

AI Has Known Failure Modes

They agree with you
Models tend to tell users what they want to hear, even when the user is wrong.
→ Fix: someone else checks
They can't grade themselves
Asked to check their own answer with no outside feedback, models rarely improve it. Sometimes they make it worse.
→ Fix: someone else checks
They favor their own work
AI judges score their own output higher than other models' output.
→ Fix: someone else checks
They skim long context
Facts buried in the middle of a long input get missed far more often.
→ Fix: one job each, written handoffs

The idea

So Treat It Like Untrusted Code

None of these rules are new. We already use them on code people write.

1
One job each
Each agent is an AI with one narrow task. Planner, builder, reviewer. Never all three.
Single Responsibility Principle
2
Written handoffs
Agents pass a JSON file, not a chat. The next agent knows exactly what it gets.
Design by Contract
3
Someone else checks
The agent that did the work never grades it. A different agent does.
Separation of Duties
4
Mistakes become rules
When a bug slips through, the system writes a new rule so it doesn't happen again.
Blameless Postmortems

Step 1 · Plan · grill-me → to-seed

The AI Interviews Me First

Before any code, an agent grills me with questions until the plan has no gaps.

A hidden 9th page still used the old code. Miss it, and the old code can't be deleted.

The answers are saved as a plan file. Then other agents try to break that plan.

Principle Requirements first. A defect caught in requirements is the cheapest one to fix.

Step 1 · Plan · checking the plan

Critics Attack. A Judge Decides.

Four cheap critic agents (Haiku) each hunt one kind of mistake. Every objection must quote the conversation as proof.

Grounding
Did the plan make anything up?
Accuracy
Did a decision get changed or go stale?
Completeness
Did we skip a case or a dependency?
Coherence
Does the plan contradict itself?
1 judge screens
Is the quote real? Does it prove the point? No proof means thrown out.
→
3 judges vote
Objections that survive go to a panel. 2 of 3 must agree.
→
Plan gets fixed
Only proven problems change the plan.
Principle Majority vote. Independent voters who are each better than chance get more accurate together.

This feature: 1 objection raised. The judge found no proof and threw it out. The plan passed clean.

Step 2 · Build · to-tasks → build-runner → lint and test runners

Small Tasks. Tests First.

Split
One agent breaks the plan into small tasks. Each task has a "done when" list.
T-0091: Move the 9 pages to the new header. Delete the old files.
Build
A builder agent takes one task. It writes a test and watches it fail. Then it writes code until the test passes.
Fail first proves the test checks something real.
Check
Separate cheap agents (Haiku) run lint, types and tests. They report pass or fail in a file.
Company page tests: 2,211 passed
Why Remember the show of hands? The builder can't say "tests pass." Only the checker's report counts.
Principle Test-driven development + fail fast. Red, green, refactor. A bad result stops the line right away.

Step 3 · Review · 07-27

A Second Reviewer Reads the Diff

The builder replaced the old page wrapper. A separate AI reviewer, one that didn't write the code, checked what the old wrapper used to do.

What the builder saw
Old wrapper deleted. New header in place. The page loads. Tests pass.
✓ Done
What the reviewer saw
The old wrapper quietly reset the page on every company switch. The new one doesn't. Company A's leftover state shows up on Company B.
✗ Bug

Like a classroom whiteboard. The old teacher wiped it between classes. The new one forgot.

Lesson When you delete code, check what it did quietly.
Principle Independent review. Models rarely catch their own mistakes. A fresh reader asks different questions.

Step 4 · Learn

A Bug Becomes a Rule

Same bug. Fixing it is not enough. We ask: which step should have caught it earlier?

Fixed · 07-28
The new header now resets the page on every company switch.
→
The gap
The interview caught the 9th page. It missed this. It never asked what the deleted wrapper did quietly.
→
The fix
Only when a plan deletes a component, a cheap agent inspects it first. One targeted question, only when it matters.
New rule in the interview skill (grill-me/SKILL.md:46)
46 Before deleting a component, check what it did quietly. Keep that behavior, or drop it on purpose?
Principle Blameless postmortem. Fix the process, not the person. Every incident ends with a change to the system.

Treat agents like untrusted code

Steal These

  • single responsibility Give each agent one job.
  • design by contract Pass work as a file, not a chat. If the shape is wrong, stop.
  • separation of duties Never let an agent grade its own work. Checking can run on a cheap model.
  • blameless postmortem When a bug slips through, write the rule that would have caught it.
