Treating AI Like
Untrusted Code

Your AI is a junior dev with root access.

You Already Do This

  • ✓ Validate user input before processing
  • ✓ Review pull requests before merging
  • ✓ Write tests before shipping
  • ✓ Typecheck your API contracts
  • ✓ Pin dependency versions

So why does your AI get to skip all of that?

"I read the whole codebase."

(It didn't.)

Would you trust a developer who skimmed 10% of the project and confidently refactored the rest?

200k tokens sounds like a lot. Your project is 2 million lines. Something gets cut. The model decides what.

Fix Decompose, don't extend. Give each agent only what it needs through typed contracts.

"That looks great!"

(It doesn't.)

Would you trust a code reviewer who has never left a single comment? Who agrees with every design decision you make?

Sycophancy is a well documented failure mode. The model optimizes for approval, not correctness.

Fix Never let the author review their own PR. Separate producer from critic structurally.

Confidently wrong.

Fluently fabricated.

Would you ship code without tests because the developer said "it works on my machine"?

An AI can generate a function that reads perfectly, references an API that doesn't exist, and explain why it's correct.

Fix Require evidence. Validate anchors against source. Force structured output through schemas, not free text.

"I also refactored auth."

(Nobody asked.)

Would you accept a PR that touched 47 files for a single line bug fix? That added three new abstractions and a README?

AI agents drift. They add features. They overengineer. They optimize for impressive over correct.

Fix One agent, one job. Contract bound output. If the contract doesn't ask for it, it doesn't ship.

Ground the Scope First

A grill session interviews decisions from the human. to-seed distills them into a structured spec. Then four independent critics try to break it.

Decisions are captured, distilled, then stress tested before a single line of code is written.

The Build Loop

Agents don't get to skip tests. The TDD cycle is baked into the build loop.

Trust, But Verify

Don't trust one search. Fan out across sources. Aggregate evidence. Require citations.

Opus decomposes. Haiku searches. Evidence is aggregated and cited.

Why Local Matters

●
Full filesystem access
Agents read real project state, not a snapshot. Fewer hallucinations because ground truth is always one grep away.
●
No sandbox tax
No VM boot, no container overhead, no file sync delays. TDD loops run at native speed.
●
Git as state machine
Worktrees for parallel agent isolation. Stash, commit, branch. Free concurrency primitives you already know.

Principles

Steal These

01
Decompose, don't extend
Many agents with small contexts beat one agent with a big context. Microservices, not monolith.
02
Adversarial by default
Never let the agent that wrote something verify it. Separate producer and critic. 2 of 3 majority beats single pass.
03
Schema over prose
JSON contracts between agents, not free text. If the shape is wrong, the pipeline stops.
04
Tier your compute
Grep doesn't need Opus. Match model cost to task complexity. Haiku for reads, Sonnet for reasoning, Opus for decomposition.

In practice

Steal These

  • verbosity System prompt plugins can cut token output 40%. Less output means less drift, lower cost, faster loops.
  • tiering Route 80% of agent work to Haiku. Same quality for reads and greps at a fraction of Opus cost. Save the big models for decomposition.
  • hooks Hooks catch destructive commands before they run. Guardrails, not guidelines. 13 blocking gates in this system.
  • contracts Treat every agent output as untrusted input to the next stage. Validate the shape. Reject bad data early.
